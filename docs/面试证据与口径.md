## SPI 缺陷应该讲清的四件事

1. **规则是什么：** START 后，本帧分频应固定，APB 写 CLKDIV 只影响下一帧。
2. **为什么旧版错：** 当前帧比较的是可变 `clkdiv_reg`。调大值会拉长半周期；调小到当前计数以下可能错过比较点。实际测试捕获的是应到的边沿缺失，没有把推导的回绕等待时间当成实测。
3. **怎么修：** START 时锁存 `clkdiv_latched`，活动计数使用它；软件配置寄存器仍可写，下一帧生效。
4. **凭什么认为修好了：** 同一批公开接口测试由 8 FAIL 转为 24 PASS；原回归仍通过；独立参考分频监视器的安全性质得到证明，cover 允许并到达忙时改分频的场景。

## 形式验证必须解释的边界

- 合法 APB setup/access 是环境假设；SCLK 分频正确是 DUT 断言。不能把输入协议约束写成验证 DUT 正确性的结论。
- 忙时修改分频没有被 assume 掉；16 位 divider、1..32 位长度、模式与数据未固定成单个测试值。
- 复位和 disable abort 是合法取消路径，相关帧义务按条件结束。
- BMC 的 FAIL 给出有限长度反例；prove 的 PASS 是这些性质在所列假设下的无界安全证明；cover 只证明场景可达。
- 18 条中包含辅助不变量，不能写成“SPI 全功能形式验证 100%”或“完整模块签核”。没有证明任意控制输入下的最终完成性。

## Bridge 深化的取舍

本轮优先修协议正确性。AXI FIXED/INCR/WRAP 的地址语义保留，下游每个 beat 使用独立 AHB SINGLE/NONSEQ，不再宣称生成 AHB 多拍 burst。地址相位接受后再等待数据相位完成，HREADY 低时不提前弹出数据；ERROR 采用真实两周期响应。

写 burst 已收齐后先预检每拍 WSTRB/WLAST，再发 AHB，使后续非法拍也满足“整笔零 AHB 副作用”的既定规格。跨 4KB、FIXED 长度及地址溢出另有检查。

这仍然是受限学习型桥接器。没有由这些结果推出 CPU LSU、精确异常、ROB、Cache/TLB 或乱序执行已经验证。
